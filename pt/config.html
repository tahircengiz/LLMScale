Decodificador de config.json — a configuração de um LLM em linguagem simples

Todo modelo no Hugging Face vem com um config.json — algumas dezenas de campos que decidem sua memória, sua velocidade e até onde ele consegue ler. Escolha um modelo e esta página responde, em linguagem simples, às perguntas que esses campos resolvem, e aponta as linhas do arquivo por trás de cada resposta.

Como a configuração é lida

O config.json é o arquivo que o Hugging Face Transformers, o vLLM e outros mecanismos de inferência leem para montar um modelo antes de carregar os pesos. Ele registra a arquitetura — camadas, larguras, cabeças de atenção, especialistas, posições, vocabulário e precisão —, mas não os pesos nem a contagem de parâmetros, que o LLMScale obtém da API do Hugging Face.

  • cache KV por token = 2 × camadas × cabeças de chave-valor × head_dim × bytes
  • com MLA = camadas × (kv_lora_rank + qk_rope_head_dim) × bytes
  • contexto máximo = max_position_embeddings (o escalonamento linear e o YaRN chegam a ele como original × fator; o escalonamento do Llama 3 não é um simples produto)
  • razão do GQA = cabeças de atenção ÷ cabeças de chave-valor

Cada resposta indica os campos que usou e os destaca no arquivo, com as contas mostradas logo abaixo. Os campos que o glossário não conhece aparecem como sem explicação, com o valor bruto, em vez de serem adivinhados. Repositórios restritos como Llama e Gemma não podem ser lidos de um navegador; para eles, a página recorre à arquitetura do banco de dados embutido do LLMScale e avisa isso.

Perguntas

Onde fica a contagem de parâmetros no config.json?
Ela não está lá. Uma configuração descreve a forma de um modelo, não o tamanho dele em disco. O LLMScale lê a contagem dos metadados do safetensors na API do Hugging Face, e é assim que a página pode mostrá-la ao lado da configuração.
Qual é a diferença entre num_attention_heads e num_key_value_heads?
num_attention_heads é quantas cabeças de consulta cada camada executa; num_key_value_heads é quantas cabeças de chave e de valor elas compartilham. Quando o segundo é menor, o modelo usa atenção agrupada por consulta, e o cache KV dele encolhe na mesma proporção — o Llama 3.1 8B compartilha 8 cabeças de chave-valor entre 32 cabeças de consulta, um quarto do cache de que a atenção MHA completa precisaria.
max_position_embeddings significa que o modelo funciona bem nesse comprimento?
Significa que o modelo está configurado para esse comprimento. Os mecanismos de inferência partem dele, mas podem usar um padrão menor — o Ollama o ajusta à sua VRAM, e o vLLM usa por padrão o comprimento original nos modelos LongRoPE. Quão bem o modelo se sai perto do limite depende de como ele foi treinado, e isso a configuração não consegue dizer.
Por que trust_remote_code importa?
Uma entrada auto_map significa que o repositório traz seu próprio código Python de modelagem, e o Transformers só o executa quando você passa trust_remote_code=True. Esse código roda com as suas permissões, então leia-o — ou prefira uma versão do modelo que o Transformers suporte nativamente.
