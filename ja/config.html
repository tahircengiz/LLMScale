config.json の解説：LLM の設定をわかりやすく

Hugging Face のどのモデルにも config.json が付いています。数十のフィールドが、メモリ、速度、どこまで読めるかを決めています。モデルを選ぶと、このページはそれらのフィールドで決まる問いにわかりやすく答え、各回答の根拠となるファイルの行を示します。

config.json の読み方

config.json は、Hugging Face Transformers、vLLM などのエンジンが、重みを読み込む前にモデルを構築するために読むファイルです。アーキテクチャ（層、幅、アテンション ヘッド、エキスパート、位置、語彙、精度）を記録しますが、重みは含まず、パラメータ数も含みません。LLMScale はパラメータ数を Hugging Face API から取得します。

  • トークンあたりの KV キャッシュ = 2 × 層数 × KV ヘッド数 × head_dim × バイト数
  • MLA の場合 = 層数 × (kv_lora_rank + qk_rope_head_dim) × バイト数
  • 最大コンテキスト = max_position_embeddings（linear と YaRN のスケーリングでは元の長さ × 係数で到達する。Llama 3 のスケーリングは掛け算にならない）
  • GQA 比 = アテンション ヘッド数 ÷ KV ヘッド数

各回答は使ったフィールドの名前を示してファイル内でハイライトし、その下に計算過程を表示します。用語集にないフィールドは推測せず、生の値とともに「説明なし」として一覧にします。Llama や Gemma のようなゲート付きリポジトリはブラウザから読めないため、ページは LLMScale の組み込みデータベースにあるアーキテクチャを代わりに使い、その旨を表示します。

よくある質問

config.json のどこにパラメータ数がありますか？
パラメータ数は含まれていません。config.json はモデルの形を記述するもので、ディスク上のサイズではありません。LLMScale は Hugging Face API の safetensors メタデータからパラメータ数を読み取り、それを config.json の横に表示しています。
num_attention_heads と num_key_value_heads の違いは何ですか？
num_attention_heads は各層が実行するクエリ ヘッドの数、num_key_value_heads はそれらが共有するキーと値のヘッドの数です。後者が小さい場合、モデルはグループ クエリ アテンションを使い、KV キャッシュは同じ比率で小さくなります。Llama 3.1 8B は 32 個のクエリ ヘッドで 8 個の KV ヘッドを共有しており、キャッシュは完全なマルチヘッド アテンションの 4 分の 1 です。
max_position_embeddings は、モデルがその長さでうまく動作するという意味ですか？
モデルがその長さ向けに設定されているという意味です。エンジンはこの値を起点にしますが、デフォルトではもっと短くすることがあります。Ollama は VRAM に合わせて調整し、vLLM は LongRoPE モデルのデフォルトを元の長さにします。上限近くでモデルがどれだけ性能を保てるかは学習方法によって決まり、config.json からはわかりません。
trust_remote_code が重要なのはなぜですか？
auto_map の項目は、リポジトリが独自の Python のモデリング コードを含むことを意味し、Transformers は trust_remote_code=True を渡したときだけそれを実行します。そのコードは実行したユーザーの権限で動作するため、内容を確認するか、Transformers がネイティブにサポートしているバージョンのモデルを選んでください。
