What the comparison measures

Put two to four models from the Hugging Face Hub side by side. Each column is resolved the same way as on the other pages: parameters, experts, maximum context, licence, downloads, likes, last update and base model; the precision the weights ship in and what they weigh; the KV cache per token at FP16; and the GPU memory needed for 8k tokens and one user.

Below that come the capabilities the Hub declares — instruct, code, math, reasoning, vision, multilingual, embedding — and the task-fit score for all 11 tasks. The best value is highlighted for context, downloads, likes and each task score; a row where every model ties stays plain.

Questions

Is the VRAM figure the same as the calculator's?
It comes from the same engine at a fixed workload: 8k context, one user, FP16 KV cache, 10% overhead and 0.75 GiB of CUDA context. Open the model in the VRAM calculator to size it for your own context and number of users.
Why does a quantized model sometimes show BF16?
When the precision cannot be detected from the quantization config, the repository name, torch_dtype or the safetensors header, the comparison assumes BF16. If the weight size looks too large, check the repository.
Which model is better for my task?
The task rows score how well each model is built for it — instruction tuning, context, size, declared capabilities. They cannot measure answer quality, so use them to shortlist, then try the finalists on your own prompts.
How many models can I compare?
Up to four at once. The selection lives in the page address, so a link opens the same comparison for someone else.
