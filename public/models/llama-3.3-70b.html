Llama 3.3 70B Instruct: how much VRAM does it need?

Llama 3.3 70B Instruct has 70.5B parameters across 80 layers. Below are its real memory requirements — weights, KV cache and overhead — by precision and context window, and the GPUs that hold it. Every figure is computed from the model's own architecture, not a rule of thumb.

BF16 · 8k context · one user
148.1 GiB

131.4 GiB of weights, 2.50 GiB of KV cache, 14.14 GiB of activations and CUDA context.

Totals for one concurrent user, FP16 KV cache, 10% activation overhead and 0.75 GiB of CUDA context. Quantizing the weights shrinks the weights only — the KV cache is unchanged, which is why the saving narrows as context grows.

How many users fit on one B200 192GB

  • BF16 (2 bytes) — about 13 concurrent users at 8k context
  • FP8 (1 byte) — about 39 concurrent users at 8k context
  • INT4 / Q4 (0.5 byte) — about 52 concurrent users at 8k context

Where the numbers come from

Weights are parameters × bytes per parameter. The KV cache is 2 × layers × kv_heads × head_dim × bytes × context × concurrency, which for this model works out to 320.0 KiB per token at FP16. Its grouped-query attention shares 64 query heads across 8 key/value heads, so the cache is 8× smaller than multi-head attention would need. GPU fit assumes about 95% of nominal VRAM is usable after the driver reserve.

These are planning figures, not guarantees: actual usage depends on the serving engine — vLLM, TGI, llama.cpp — and on paged-attention efficiency.
