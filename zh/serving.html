推理服务简报——模型仓库关于如何为它提供推理服务的说明

模型仓库里不只有 config.json。聊天模板决定工具调用和思考，generation_config.json 决定默认采样设置和回复何时结束，张量名称则显示哪些部分真正被量化、多 token 预测层是否随附。选择一个模型：本页会在你的浏览器中读取这些文件，标出可能让部署出问题的地方，并写出它们所需的 vLLM 和 SGLang 参数。

如何读取仓库

本页像引擎在加载仓库前那样读取它：从 Hugging Face API 获取文件列表和大小；如果仓库中有，则读取 config.json、generation_config.json、tokenizer_config.json 或 chat_template.jinja、hf_quant_config.json、adapter_config.json 和 params.json；张量名称则从 model.safetensors.index.json 读取，单文件模型则从 safetensors 文件头读取，这只需两个小的范围请求，而不必下载。全部过程都在你的浏览器中运行。

只有当 vLLM 0.31.0 或 SGLang 0.5.21 在其文档或 parser 注册表中列出某个参数时，本页才会写入它；对于两者都未提及的模型系列，本页不写参数，也不去猜测。MTP 支持情况来自各引擎用于构建草稿模型的代码。显存、并行和批处理交由显存估算页面和 vLLM 页面处理。

常见问题

什么是 MTP，为什么要检查张量？
多 token 预测层是经过训练、用于预测更靠后 token 的额外层。vLLM 和 SGLang 可以把它们当作内置草稿模型用于推测解码。config.json 只说明应该有多少层，而量化版本有时会把它们丢掉：DeepSeek-V3 的 AWQ 版本声明了一个 MTP 层，却没有附带原版为此准备的 1,564 个张量中的任何一个。所以本页会检查张量名称。
为什么 generation_config.json 很重要？
vLLM 和 SGLang 从中获取默认的 temperature、top_p 和 top_k，以及结束回复的 token。Qwen3 的该文件列出了两个结束 token，而它的 config.json 只列出一个；gpt-oss 的则多出两个。vLLM 还会把其中的 max_new_tokens 变成服务器级上限。
模型需要哪个工具调用 parser？
能读取其聊天模板所写格式的那个：Qwen 是 <tool_call> 块中的 JSON，gpt-oss 是 harmony 通道，Qwen3-Coder 是 <function=…> XML。本页读取模板和模型类型，并给出各引擎文档为该模型系列指定的 parser。不同引擎的名称不同：Qwen 在 vLLM 中是 hermes，在 SGLang 中是 qwen。
仓库声明的量化方式可信吗？
通常可以，但张量名称才是证据。带块缩放因子的 FP8 会留下 weight_scale_inv 张量，NVFP4 留下 weight_scale_2，MXFP4 留下 _blocks 和 _scales，AWQ 和 GPTQ 留下 qweight 和 qzeros。NVIDIA 的 NVFP4 检查点在 hf_quant_config.json 而不是 config.json 中声明量化方式。本页两者都会读取，并在名称与声明不一致时指出。
