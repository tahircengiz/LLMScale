对比展示了什么

从 LLMScale 收录的 45 款设备中挑选两到四款：消费级和工作站显卡、数据中心 GPU、Apple Silicon 以及统一内存 AI PC。每一列就是该设备的数据表：架构、芯片与制程、核心数与发布时间；显存及其类型、位宽和带宽；BF16、FP8 和 FP4 下的稠密张量算力；功耗、外形规格、两块之间的互连、MIG 分区，以及在其上提供模型服务的引擎。

只要厂商公布，每项数据都取自厂商的产品页面、数据表或白皮书；厂商未公布的，则取自注明出处的二手来源；没有任何来源能确定的数值留空，而不做猜测。当各列数值不同时，显存、带宽和张量算力各行中的最佳值会高亮显示。要查看某个模型在这些卡上需要什么，请打开显存计算器。

常见问题

运行 LLM 时，这些数字中哪个最重要？
显存决定能放下什么：权重，以及每个用户上下文所需的 KV 缓存。带宽决定单个用户看到 token 的速度，因为每个 token 都要把每个权重读取一遍；1,792 GB/s 的 RTX 5090 为单个用户生成的速度约为 864 GB/s 的 L40S 的两倍，尽管 L40S 的 BF16 额定算力更高。张量算力决定提示的读取速度以及大批次能扩展到什么程度。
为什么这里的某些 TFLOPS 数值比厂商页面上的低？
NVIDIA 经常按 2:4 结构化稀疏标注张量算力，这会让数值翻倍，但只适用于按该模式剪枝过的权重——而几乎没有哪个用于推理服务的 LLM 是这样剪枝的。LLMScale 列出的是稠密算力；如果厂商只印出稀疏值，就取其一半。GeForce 显卡按 FP32 累加的算力列出，即 FP16 累加算力的一半。
统一内存对 LLM 意味着什么？
CPU 和 GPU 共享一个内存池，因此小设备也能容纳大模型——但默认情况下 GPU 只能寻址其中一部分：36 GB 及以上的 Mac 为四分之三，以下为三分之二；Windows 下的 Strix Halo 为 128 GB 中的 96 GB；DGX Spark 上几乎是全部。它们的带宽也只有显卡的几分之一，因此能装下大模型，但运行得很慢。
