Ringkasan penyajian — apa yang dikatakan repositori model tentang cara menyajikannya

Repositori model berisi lebih dari config.json. Template chat menentukan pemanggilan alat dan proses berpikir, generation_config.json menentukan default sampling dan kapan balasan berakhir, dan nama tensor menunjukkan apa yang benar-benar dikuantisasi serta apakah lapisan multi-token prediction ikut dirilis. Pilih model: halaman ini membaca file-file itu di browser Anda, menandai hal yang dapat menggagalkan deployment, dan menuliskan flag vLLM dan SGLang yang diperlukan.

Pilih model untuk membaca repositorinya

Atau mulai dari salah satu berikut:

Setelah model dipilih, halaman ini menjawab:

  • Apa isi repositori ini?
  • Bagaimana model ini melakukan chat — alat, proses berpikir, gambar?
  • Pengaturan sampling apa yang disertakan?
  • Bagaimana bobotnya disimpan?
  • Bisakah model ini membuat draf tokennya sendiri (MTP)?
  • Untuk konteks sepanjang apa model ini dikonfigurasi?
  • Apa yang dibutuhkan untuk memuatnya?

Cara repositori dibaca

Halaman ini membaca repositori seperti yang dilakukan mesin inferensi sebelum memuatnya: daftar file dan ukurannya dari API Hugging Face; config.json, generation_config.json, tokenizer_config.json atau chat_template.jinja, hf_quant_config.json, adapter_config.json, dan params.json jika ada di repositori; serta nama tensor, dari model.safetensors.index.json atau, untuk model satu file, dari header safetensors, yang hanya membutuhkan dua permintaan rentang kecil, bukan unduhan penuh. Semuanya berjalan di browser Anda.

Sebuah flag hanya ditulis jika vLLM 0.31.0 atau SGLang 0.5.21 menyebutkannya, di dokumentasi atau registri parser-nya; keluarga model yang tidak disebutkan oleh keduanya tidak mendapat flag, alih-alih tebakan. Dukungan MTP diambil dari kode yang dipakai setiap mesin inferensi untuk membangun model drafnya. Memori, paralelisme, dan batching diserahkan ke halaman perhitungan VRAM dan halaman vLLM.

Pertanyaan

Apa itu MTP, dan mengapa tensornya diperiksa?
Lapisan multi-token prediction (MTP) adalah lapisan tambahan yang dilatih untuk memprediksi token yang lebih jauh ke depan. vLLM dan SGLang dapat memakainya sebagai model draf bawaan untuk decoding spekulatif. config.json hanya menyebutkan berapa jumlah yang seharusnya ada, dan salinan yang dikuantisasi terkadang membuangnya: salinan AWQ DeepSeek-V3 mendeklarasikan satu lapisan MTP, tetapi tidak menyertakan satu pun dari 1.564 tensor yang dimiliki model aslinya untuk lapisan itu. Karena itu halaman ini memeriksa nama tensor.
Mengapa generation_config.json penting?
vLLM dan SGLang mengambil nilai default suhu, top_p, dan top_k dari file ini, juga token yang mengakhiri balasan. File milik Qwen3 mencantumkan dua token akhir, sementara config.json-nya mencantumkan satu, dan file milik gpt-oss menambahkan dua. vLLM juga menjadikan max_new_tokens di file ini sebagai batas untuk seluruh server.
Parser panggilan tool mana yang dibutuhkan sebuah model?
Parser yang membaca format yang ditulis oleh template chat model itu: JSON dalam blok <tool_call> untuk Qwen, kanal harmony untuk gpt-oss, XML <function=…> untuk Qwen3-Coder. Halaman ini membaca template dan jenis modelnya, lalu menyebutkan parser yang diberikan dokumentasi setiap mesin inferensi untuk keluarga tersebut. Namanya berbeda antar-mesin: Qwen adalah hermes di vLLM dan qwen di SGLang.
Bisakah saya memercayai kuantisasi yang dideklarasikan sebuah repositori?
Biasanya bisa, tetapi buktinya ada pada nama tensor. FP8 dengan skala blok meninggalkan tensor weight_scale_inv, NVFP4 weight_scale_2, MXFP4 _blocks dan _scales, AWQ dan GPTQ qweight dan qzeros. Checkpoint NVFP4 dari NVIDIA mendeklarasikan kuantisasinya di hf_quant_config.json, bukan di config.json. Halaman ini membaca keduanya, dan memberi tahu jika nama tensor dan deklarasinya tidak cocok.
